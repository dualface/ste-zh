# 术语与固定译法

本文件规定 ste-zh 使用的全部关键词。使用本 skill 时，必须按本表翻译和用词。表中没有的词，按 R1 在输出的「术语」节中自行固定。

## 2. 情态词

全文只用以下三个情态词。

| 用词 | 词义 | 不得使用的近义词 |
|---|---|---|
| 必须 | 强制要求 | 应、应当、应该、需要、务必、要 |
| 不得 | 禁止 | 不应、不要、避免、禁止、切勿、不允许 |
| 可以 | 允许，不强制 | 可、能够、允许、可选 |

本表只限制情态用法。情态用法指表示要求、禁止或允许的用法。以下用法不受本表限制：

- 「需要」表示缺少或依赖某物。例：「读者需要的证据」。
- 固定用词「要做」。见第 5 节。

例外：引用来源原文时，保留原文用词，并用引号标出。

## 3. 虚化动词替换表

以下写法把动作包装成名词。必须改为直接动词。

| 不得使用 | 改写为 |
|---|---|
| 对 X 进行修改 / 处理 / 检查 | 修改 / 处理 / 检查 X |
| 实现 X 功能 | 增加 X；或写出 X 的具体行为 |
| 予以 X / 加以 X | X |
| 做好 X 工作 | X |
| 完成 X 的操作 | X |
| 将会 X | 会 X |
| 进行 X | X |
| 作出 X 决定 | 决定 X |
| 通过 X 的方式 | 用 X |
| 存在 X 问题 | 写出具体现象 |
| 有一定的 X | 写出具体的量；没有量时删除 |

「处理」本身也是虚化动词。能写出具体动作时，不用「处理」。

## 4. 状态词

写工作状态时，只用以下词，并只按表中的词义使用。

| 状态词 | 词义 | 不得替换为 |
|---|---|---|
| 已完成 | 动作全部执行，结果符合要求。 | 搞定、OK、done、基本完成 |
| 部分完成 | 一部分动作已执行。必须列出没有执行的部分。 | 基本完成、大致完成 |
| 未开始 | 没有执行任何动作。 | 待办、TODO |
| 进行中 | 动作已开始，没有结束。 | 处理中、跟进中 |
| 已验证 | 执行了检查，检查通过。必须写出检查方法。 | 已测试、应该没问题 |
| 未验证 | 没有执行检查。必须写出原因。 | 理论上可行、应该可以 |
| 失败 | 执行了动作或检查，结果不符合要求。必须写出失败的输出。 | 有点问题、不太行 |
| 跳过 | 有意没有执行。必须写出原因。 | 略过、忽略 |
| 阻塞 | 缺少条件，不能继续。必须写出缺少的条件。 | 卡住、受阻 |
| 未确认 | 事实没有核实。必须写出核实方法。 | 可能、大概、应该是 |

「完成」不得单独用来表示「已验证」。改动已完成但没有检查时，写「已完成，未验证」。

## 5. 模板的固定用词

| 用词 | 用途 | 不得替换为 |
|---|---|---|
| 术语 | 定义专用词的节 | 名词解释、词汇表、定义 |
| 共同条件 | 所有项都适用的事实或约束 | 前提、背景、通用约束 |
| 问题 | 一项工作的现状 | 现状、缺陷描述、痛点 |
| 要做 | 一项工作必须达到的可检查结果 | 方案、措施、修复内容、TODO |
| 改动 | Agent 修改了的文件或配置 | 变更内容、修改点、diff |
| 验证 | 检查及其结果 | 测试情况、自测 |
| 未做 | 范围内没有执行的事 | 遗留、后续、TODO |
| 现象 | 用户看到的行为 | 表现、症状 |
| 原因 | 现象的直接来源 | 根因分析、问题所在 |
| 证据 | 支持一个事实的来源位置 | 依据、出处 |
| 建议 | Agent 推荐的下一个动作 | 方案、解决思路 |
| 待确认 | 由用户决定的事项，或来源缺少的内容 | 风险、TBD、遗留问题 |
| 推荐 | 选项列表中 Agent 推荐的一项 | 建议选择、首选 |

## 6. 标点与混排

- 中文正文用全角标点：「，。；：（）」。
- 引用界面文案或强调词语用直角引号「」。
- 代码、命令、路径、标识符写在反引号内，内部保持半角。
- 中文与英文单词、数字之间加一个半角空格。中文与全角标点之间不加空格。
