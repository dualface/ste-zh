# 示例：任务卡总结

本示例的来源是虚构的。

## 改写前

> 本迭代需要对移动端登录模块进行优化处理，主要包括以下几方面：一是针对弱网环境下登录请求经常超时、用户体验较差的问题，要做好重试机制的实现工作，重试不超过三次；二是会话过期后用户无法感知，需要予以提示；三是密码输入框在部分机型上存在被键盘遮挡等问题。另外，第三方登录暂不考虑。

不合格之处：

- 「进行优化处理」「做好……实现工作」「予以提示」是虚化动词（R3）。
- 一句包含多个动作（R6）。
- 「需要」「要」词义不固定（R11）。
- 「等问题」是开放式列举（R17）。
- 「体验较差」不是可检查的结果。

## 改写后

### 术语
- **会话**：登录成功后，服务端保留的登录状态。

### 共同条件
- 只改移动端登录模块。
- 不做第三方登录。

### 1. 登录
**Retry Login Requests on Weak Networks**（large，Bug）
- 问题：网络信号弱时，登录请求经常超时。超时后，用户必须手动重新登录。
- 要做：
  - 登录请求超时时，自动重试。
  - 重试最多 3 次。
  - 3 次都失败时，显示超时错误和「重试」按钮。

**Notify Users When the Session Expires**（small，Bug）
- 问题：会话过期后，应用不提示用户。
- 要做：
  - 会话过期时，显示提示。
  - 用户点击提示后，打开登录页。

**Keep the Password Field Above the Keyboard**（small，Bug）
- 问题：在部分机型上，键盘挡住密码输入框。
- 要做：
  - 键盘弹出时，密码输入框保持在键盘上方。

### 待确认
- 「部分机型」的具体型号清单。来源没有列出。

## 说明

- 第三张卡的「部分机型」在来源中没有清单。改写不得自行补充型号，因此列入「待确认」。
- 「重试最多 3 次」来自来源的「重试不超过三次」。来源没有规定次数时，不得自行写次数，必须把次数列入「待确认」。
